# Mustache template reference

allcrud-generator's custom templates (`src/main/resources/templates/`), consolidated from what
used to be a near-identical header comment repeated at the top of each file. openapi-generator
version referenced throughout: **7.23.0** (pinned in `build.gradle.kts` as `openapiGeneratorVersion`).

| Template | Overrides a stock openapi-generator template? | Notes |
|---|---|---|
| `apiController.mustache` | Yes - `JavaSpring/apiController.mustache` | Drops the stock delegate pattern entirely in favor of extending `CrudController<T, VO, ID>` directly. |
| `converter.mustache` | No - brand-new | The stock "spring" generator has no converter template at all; not related to any file also named `converter.mustache` elsewhere in openapi-generator. |
| `generatedAnnotation.mustache` | Yes - `JavaSpring/generatedAnnotation.mustache` | The stock partial emits `@Generated`; overridden for allcrud-generator's own attribution comment ("Generated by allcrud-generator - customize the implementation below."). |
| `integrationTest.mustache` | No - brand-new | The stock "spring" generator has no integration-test template. |
| `model.mustache` | Yes - `JavaSpring/model.mustache` | |
| `pojo.mustache` | Yes (the model body it's included from is an override of the stock model shape) | Implements `AbstractEntityVO<ID>`/`AbstractEntityDTO<ID>` (switch: `allcrudUseDto`, see model.mustache) instead of the original `vendorExtensions.x-implements` loop. ID type comes from `vendorExtensions.allcrudIdType`, resolved per-model by `AllcrudSpringCodegen#postProcessModels`. |
| `repository.mustache` | No - brand-new | The stock "spring" generator has no repository template. |
| `service.mustache` | No - brand-new | The stock "spring" generator has no service-layer template at all. |
| `unitTest.mustache` | No - brand-new | The stock "spring" generator has no unit-test template at all. |

See ADR [0001](adr/0001-generate-once-never-overwrite.md) for why these templates' *output* is
never overwritten once generated - this document only covers the templates themselves, not their
generated files' lifecycle.
